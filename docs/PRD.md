## 1. 프로젝트 개요

### 한 줄 요약
부산·경남 입주청소 업체 감탄이 하청 구조에서 **직접 영업으로 넘어가기 위한** 1인 관리자용 운영 시스템. 정산·일정·영업·상담·회계를 한곳에서 자동화한다.

### 배경 및 목적
- 현재 아는 팀장님(자체 영업 + 크린토피아, 이후 미소 추가 예정)에게 카카오톡으로 일을 받아 주 8~10건 진행. 하청이라 마진이 낮다.
- 직접 수주로 마진을 키우려 하지만, **고객이 찾아올 통로가 없고** 마케팅·상담 부담 때문에 시작하지 못하고 있다.
- 이 시스템의 가치: ① 정산 자동화·기록(당장 필요) ② 마케팅·상담 부담 감소(가장 큰 가치)

### 타겟 사용자
| 사용자 | 접근 범위 |
|---|---|
| 대표 (1인) | 전체 기능. 구글 계정 로그인 |
| 외부 팀장님 (2팀 운영 시) | 로그인 없음. 팀별 공유 구글 캘린더 + 읽기 전용 정산표 링크 |
| 고객 | 시스템 로그인 없음. 견적 페이지·카카오톡 채널 챗봇으로만 접점 |

### 현재 업무 흐름
```
팀장님 ──카카오톡──▶ 캘린더 등록 ──▶ 해피콜(전화·카톡) ──▶ 현장 투입 ──▶ 정산
크린토피아 ──문자──▶ (아이폰 자동화로 구글 캘린더 자동 등록, 사용 중)
```

### 현재 도구
- 일정·정산: 구글 캘린더 + 기존 정산 페이지(Node 함수 2개 + 정적 HTML + Redis)
- 회계: 구글 시트
- 마케팅: 블로그만 운영했음. 인스타는 계정만 있음
- 예정 채널: 네이버플레이스, 인스타그램, 당근, 숨고, 미소

### 기존 자산
- 기존 공개 홈페이지: Next.js 14 (`endrmsakdmf/gamtan`, `gamtan.vercel.app`). **이전하지 않는다** (2026-11-08 결정)
  - 대신 새 공개 홈페이지를 이 계정(`woomyshipping-hub`)에서 새로 만든다. M2에서 견적 페이지와 연결한다 (기능 10)
  - 전화번호·서비스 지역 같은 브랜드 정보는 실제 값을 그대로 쓴다
- 정산 페이지: `endrmsakdmf/gamtan` 브랜치 `claude/sleepy-ride-2e0dyk`의 `settle-deploy/` → 이 저장소 루트로 이전 완료 (M0)
  - 규칙: `handoff.json`, 기대값: `fixtures.json`, 검증: `node verify.js` → `TOTAL pass=41 fail=0`, `node verify.js --url https://gamtan-kr.netlify.app` → `TOTAL pass=64 fail=0` (2026-11-08 확인)
  - 화면 문구(킴 / 김한준님 / 정산받을 총액)와 규칙, `handoff.json`·`fixtures.json`은 대표 확인 없이 변경 금지

## 2. 핵심 기능

### 기능 1: 정산
- 설명: 기존 정산 규칙을 그대로 이전하고 기록을 보관한다
- 우선순위: MVP (M0)
- 상세:
  - `handoff.json`의 규칙과 `fixtures.json`의 기대값을 그대로 이식한다. 41건 검증을 통과해야 한다
  - 정산 이력을 월별·팀별로 조회한다
  - 기존 Redis 상태 데이터를 DB로 이전한다 (`handoff.json`의 `data_migration` 참고)

### 기능 2: 일정·현장 관리
- 설명: 건별 상태 추적과 팀 단위 배정
- 우선순위: MVP (M1)
- 상세:
  - 상태: 접수 → 확정 → 완료 → 정산됨
  - 팀 배정: 1팀(대표 + 김한준 팀장님 고정) / 2팀(외부 팀장님 계약) / 추가 일용직
  - 팀별 구글 캘린더에 일정 동기화. 일정마다 해당 건의 정산 금액을 표시한다
  - 외부 팀장님용 읽기 전용 정산표 링크 (해당 팀 데이터만, 로그인 없음)

### 기능 3: 일정 자동 입력
- 우선순위: 붙여넣기는 MVP (M1), 자동 읽기는 이후
- 상세:
  - 크린토피아 문자: 기존 아이폰 자동화를 유지한다
  - 카카오톡(팀장님): 1단계로 메시지를 복사해 붙여 넣으면 AI가 날짜·주소·평수·옵션을 추출해서 일정 초안을 만든다. 대표가 확인 후 등록한다
  - 2단계: 안드로이드 공기계 알림 전달 → 자동 등록 (카카오 공식 API 없음, 약관상 회색지대임을 인지)

### 기능 4: 견적
- 우선순위: M2
- 상세:
  - 평당 요금을 화면에서 변경할 수 있게 한다. 1만~1.3만 원 구간을 테스트한다
  - 요금별 견적 수·수주 수를 기록해서 어떤 요금이 효과적인지 비교한다
  - 추가요금은 크린토피아 추가 규칙을 따른다
  - 고객용 견적 페이지: 평수, 날짜, 주소, 옵션 입력 → 즉시 견적 → 문의 접수
  - 숨고·미소 견적 요청: 요청 내용을 붙여 넣으면 견적 계산과 답장 초안을 만든다 (공개 API가 없어 자동 발송은 불가)

### 기능 5: AI 상담
- 우선순위: M3
- 상세:
  - 카카오톡 채널 챗봇(공식 오픈빌더 스킬 서버)과 견적 페이지에서 AI가 1차 응대한다: 가격, 가능 날짜, 서비스 범위 안내
  - 반응이 있는 고객을 선별해서 **전화 상담 리스트**를 만든다
  - 텔레그램 봇으로 알리고, 상담 예정 건을 구글 캘린더에 등록한다
  - 대표가 전화 상담 → 결과(수주/보류/실패)를 기록한다

### 기능 6: 고객 관리·후속 영업
- 우선순위: 고객 목록은 M2, 후속 메시지는 M4
- 상세:
  - 문의·견적·수주 이력과 유입 채널을 기록한다
  - 광고성 정보 수신 동의를 받아 저장한다 (동의 일시, 경로)
  - 수신에 동의한 고객에게만 후속 영업 메시지를 보낸다. "(광고)" 표기와 수신거부 안내를 넣고, 21시~08시에는 보내지 않는다 (정보통신망법)
  - 발송 채널은 카카오톡 채널(친구 추가 고객)이다. 유료 문자·알림톡은 초기에 쓰지 않는다

### 기능 7: 마케팅 자동화
- 우선순위: M2~M4
- 상세:
  - (a) 현장 사진 업로드 → 블로그·인스타·당근 글 자동 생성 (M2). 게시는 대표가 확인한 뒤 한다. 인스타는 비즈니스 계정 API로 자동 게시를 검토한다
  - (b) 숨고·미소 견적 답장 초안 (M2, 기능 4)
  - (c) 채널별 문의를 한곳에서 보기 (M4)
  - (d) 작업 완료 후 리뷰 요청 링크 자동 발송 (M2). 실제 고객 리뷰로 20건을 확보하는 것이 목표다
  - (e) 광고비 대비 문의·수주 효과 대시보드 (M4)

### 기능 8: 회계·세무
- 우선순위: 기본 장부는 M1, 부가세 자료는 M3, 종소세 자료는 런칭 후
- 상세:
  - 수입·지출 장부 (구글 시트를 대체). 영수증 사진을 첨부할 수 있다
  - 경비 분류: 인건비, 차량, 장비, 세제, 통신비 등
  - 일용직 지급 기록 → 일용근로소득 지급명세서 자료 (매월 신고)
  - 부가세 신고 자료 (첫 신고는 2027년 1월), 종합소득세 자료 (2027년 5월)
  - 세금계산서 발행은 홈택스에서 직접 한다 (자동 발행 API는 유료라 제외)
  - 일용직 주민등록번호는 화면에서 가려서 표시하고, 신고 자료를 출력할 때만 전체를 노출한다
  - 원칙: 모든 매출을 기록한다. 세금은 경비 처리, 인건비 신고, 과세 유형 판단, 공제 항목 같은 **합법적 방법**으로 줄인다

### 기능 10: 공개 홈페이지 (신규)
- 우선순위: M2
- 설명: 기존 홈페이지(`gamtan.vercel.app`)를 옮기지 않고, 이 저장소 계정에서 새로 만든다. 직접 영업의 첫 접점
- 상세:
  - 견적 페이지(기능 4)와 같은 사이트로 연결한다. 홈페이지 → 즉시 견적 → 문의 접수
  - 리뷰(실제 고객), 시공 사진, 서비스 지역(부산·경남), 연락처(실제 전화번호), 카카오톡 채널 링크
  - 검색 노출 허용 (운영 시스템 화면은 계속 `noindex`)
  - 화면 작업에는 디자인 스킬(impeccable, design-taste-frontend)을 쓴다

### 기능 9: 성과 대시보드
- 우선순위: M4
- 상세: 주간 수주 건수(목표 20건), 팀별 처리 건수(목표 각 10건), 채널별 문의 수와 수주율

## 3. 기술 아키텍처

### 스택 구성
| 영역 | 선택 | 비고 |
|------|------|------|
| 프론트엔드 | Next.js (App Router) + TypeScript + Tailwind | 홈페이지와 같은 기술 |
| 백엔드/DB | Supabase (Postgres, Storage) | 정산 기록, 고객, 장부, 현장 사진. 무료 플랜(7일 동안 사용이 없으면 일시정지) |
| 인증 | Supabase Auth + 구글 로그인 | 대표 구글 계정 1개만 허용, 로그인 유지 기간 길게 |
| 배포 | Netlify | GitHub push 시 자동 배포, 예약 작업(Scheduled Functions) 사용. Vercel은 2FA 문제로 제외 |
| 알림 | 텔레그램 봇, 사이트 안 알림, 구글 캘린더 | 무료 |
| AI | Claude API | 단순 작업(카톡 해석, 분류)은 저가 모델, 글 작성·고객 응대는 상위 모델 |
| 외부 연동 | Google Calendar API(서비스 계정), 카카오톡 채널 오픈빌더, Instagram Graph API(검토) | |
| 저장소 | GitHub `woomyshipping-hub/gamtan` | |

### 아키텍처 다이어그램
```
[고객] ─ 견적 페이지 / 카카오톡 채널 챗봇 ─┐
[숨고·미소·당근] ─(대표가 붙여넣기)──────────┤
[팀장님 카톡] ─(붙여넣기 → AI 해석)───────────┤
                                            ▼
                    Next.js on Netlify ── Claude API
                        │       │
                  Supabase   Google Calendar (팀별) ─▶ 외부 팀장님 휴대폰
                        │
                  텔레그램 봇 ─▶ 대표 (상담 리스트, 새 문의)
```

### 주요 기술 결정사항
- **Netlify 선택:** Next.js를 설정 없이 지원하고, 잠들지 않으며, 예약 작업이 기본으로 있고, 가입이 쉬움
- **Supabase 선택:** DB, 로그인, 파일 저장을 하나로 해결하고 무료로 시작할 수 있음. 기존 Redis는 이전 후 폐기
- **채널 제약:** 숨고·당근·미소는 공개 API가 없어 자동 응대 불가. 그래서 AI 응대의 중심은 카카오톡 채널과 견적 페이지이고, 다른 채널은 이쪽으로 고객을 유도한다
- **개발 환경:** Claude Code 클라우드 세션을 기본으로 쓴다. 맥북, 데스크톱, 휴대폰 어디서든 같은 환경이고 PC에 설치할 게 없다
  - 비밀값: 클라우드 환경 설정과 Netlify 환경변수에 저장. Bitwarden에 백업 (2FA 복구 코드 포함)
  - 로컬에서 실행할 때: `git clone` → `npm install` → `netlify link` → `netlify dev` (`npm run setup`으로 한 번에 실행)
  - graphify로 코드 그래프를 관리해서 토큰을 절약한다 (`graphify update .`)
- **비용 원칙:** 최소. 예상 월 비용은 AI 사용료 1만 원 안팎이고 나머지는 무료 플랜

## 4. MVP 범위

### 포함 (M0~M1)
- 정산 이전 (41건 검증) + 기록 조회
- 캘린더 상태 관리 + 팀 배정 + 팀별 캘린더 동기화
- 카톡 붙여넣기 → AI 해석 → 일정 등록
- 기본 장부 (수입·지출, 일용직 지급 기록)
- 구글 로그인, 텔레그램 알림

### 제외 (2차 이후)
- 새 공개 홈페이지, 견적 페이지, 리뷰 요청, 고객 목록, 콘텐츠 생성 → M2 (채널 오픈에 맞춤)
- AI 1차 응대, 부가세 자료 → M3
- 후속 영업 메시지, 채널 통합, 광고 대시보드 → M4
- 종소세 자료, 카톡 자동 읽기 → 런칭 후

### 명시적 제외
- 직원·고객 로그인 (팀장님은 캘린더와 읽기 전용 링크만 사용)
- 숨고·당근·미소 자동 응대 (초안 생성만)
- 세금계산서 자동 발행, 유료 문자·알림톡
- 매출 누락, 장부 이원화 기능
- 수신 동의 없는 광고 메시지 발송
- 실제 이용하지 않은 사람의 리뷰를 만드는 기능

### 디자인 스킬 설치 ✅ (2026-11-08, impeccable 4.8.1 · design-taste-frontend 2.5.1)
- 설치 위치: `.claude/skills/impeccable`, `.claude/skills/design-taste-frontend`, 훅·환경변수는 `.claude/settings.json`
- 클라우드 세션에서는 `impeccable.style`이 막혀 있어 GitHub 원본(`pbakaus/impeccable`, `Leonxlnx/taste-skill`)의 같은 버전 파일을 복사했다. impeccable 엔진은 첫 실행 때 GitHub 릴리스에서 받고 체크섬을 검증한다
- 업데이트: 맥북·데스크톱에서 아래 명령을 다시 실행하고 커밋한다

- 대상: 새 공개 홈페이지와 정산 페이지(이후 운영 시스템 화면 포함) **둘 다**. 둘 다 이 저장소 계정에 있으므로 이 저장소에 한 번 설치한다
- 시점: M0에서 정산 페이지 화면을 처음 손대기 전, 그리고 홈페이지 디자인 작업 전
- 방법: 각 저장소에 프로젝트 범위로 설치하고 커밋한다 (맥북, 데스크톱, 클라우드에서 공통으로 사용)
  - Impeccable: `npx impeccable install --providers=claude --scope=project` (디자인 훅 설치: yes)
  - Taste: `npx skills add https://github.com/Leonxlnx/taste-skill --skill "design-taste-frontend"`
  - 설치 전에 각 SKILL.md를 읽고 확인한다
  - Impeccable 라이브 모드를 쓸 경우 `IMPECCABLE_LIVE_COPY_AGENT=chat`으로 설정한다 (권한 확인 없이 실행되는 것을 방지)
- 정산 페이지: 디자인만 바꾸고 문구(킴 / 김한준님 / 정산받을 총액)와 규칙은 유지한다. 바꾼 뒤 `node verify.js`로 41건, `--url`로 64건 통과를 확인한다
