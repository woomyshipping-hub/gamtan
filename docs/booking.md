# 고객 예약 (2026-11-14)

고객이 빈 날짜를 고르고 집 정보를 넣으면 견적이 바로 나오고, 예약금 입금이 확인되면 자동으로 확정된다.

| 화면·API | 쓰는 사람 | 하는 일 |
|---|---|---|
| `/reserve/` | 고객 (로그인 없음) | 달력 → 집 정보 → 견적 → 예약 신청 → 계좌 안내 → 입금되면 화면이 "예약 확정"으로 바뀜 |
| `/bookings/` | 대표 (장부와 같은 비밀 키) | 예약 목록, 짝을 못 찾은 입금 연결, 수동 확정·취소, 단가·예약금·계좌 설정 |
| `/api/booking` | 예약 페이지 | 날짜별 열린 시간대(다른 일정 내용은 안 보냄), 예약 저장, 예약 조회(신청 때 받은 토큰으로만) |
| `/api/deposit` | 아이폰 자동화 / Apps Script | 입금 알림 원문 → 예약 대조 → 확정 + 캘린더 등록 |
| `/api/booking-admin` | 관리 화면 | 목록·처리·설정 저장 |

## 예약 불가 날짜
- 정산 캘린더에 `[크린토피아]` `[자체영업]` `[홈클린마스터]` `[감탄예약]` 일정이 있는 날 (제목에 `취소확인`이면 제외)
- `[휴무]` 일정이 있는 날 (종일 일정으로 여러 날 막기 가능) — 대표가 쉬는 날은 캘린더에 `[휴무]`만 넣으면 된다
- 입금을 기다리는 예약(대기 시간 안)과 확정된 예약이 있는 날
- 오늘+`lead_days` 전, 오늘+`max_days` 뒤, 쉬는 요일
- 마감 기준은 설정에서 고른다: **하루 단위(기본, 일정 있는 날은 전체 마감)** / 오전·오후 따로

## 견적 (`public/assets/quote.js`, 화면과 서버가 같은 코드)
`평수 × 평당 요금` + 기본 포함 개수를 넘는 방·화장실·베란다 × 1개당 요금 + 지역 출장비 → 최소 금액 → 1,000원 단위 올림. 예약금은 고정 금액(총액보다 크면 총액). 최대 평수를 넘으면 온라인 예약 대신 상담 안내.
- **지금 값은 임시 기본값**(평당 12,000원, 최소 150,000원, 방3·화2·베2 포함, 추가 방 2만·화장실 3만·베란다 2만, 출장비 0, 예약금 5만, 대기 2시간). 대표가 `/bookings/` 설정에서 확정한다.
- 신청 시점 견적 내역은 예약에 저장된다(나중에 단가를 바꿔도 이미 받은 예약 금액은 그대로).

## 혜택·장점 (2026-11-14, 대표 검토 중인 초안)
- 예약 페이지 맨 위 띠("지금 온라인 예약하면 N만 원 상당 서비스 무료"), 혜택 상자(마감일·선착순 남은 건수), 장점 카드, 견적 칸 혜택 목록
- 설정(`/bookings/` → 혜택·장점): 켜기/끄기, 이름, 신청 마감일, 선착순 건수, 무료 서비스(`이름=정상가`), 장점(`제목 | 설명`)
- 신청 순간 혜택이 적용되면 예약에 저장되고(`bookings.promo`), 확정 시 캘린더 메모에 `혜택: …` 줄이 들어간다(현장에서 빠뜨리지 않게). 선착순은 혜택을 받은 입금 대기·확정 예약 수로 센다(시간 초과·취소는 다시 풀림)
- 초안 값(피톤치드 5만·실리콘 3만·스팀 3만 상당, 7일 재방문, 12/31까지, 선착순 20건, 장점 6개)은 모두 대표 확인 전 임시. "○원 상당"은 실제 정상가가 있어야 한다(표시광고법)

## 입금 자동 확인
1. 은행 입금 문자 → 서버로 전달 (둘 중 하나)
   - **아이폰 단축어(권장)**: 자동화 → 메시지 → "메시지에 '입금' 포함" + 보낸 사람 = 은행 번호 → 즉시 실행 → 동작 "URL 내용 가져오기": `https://gamtan-kr.netlify.app/api/deposit`, 방법 POST, 헤더 `Authorization: Bearer <INBOX_TOKEN>`, 본문 "파일" = 단축어 입력(메시지 본문). 본문은 맨 텍스트로 보내도 된다.
   - 메일 경유: 크린토피아와 같은 방식으로 제목 `감탄입금` 메일을 보내고 `tools/gmail-bank.gs` 설치
2. 서버가 대조: 금액(입금 옆 숫자, 잔액 제외) ≥ 예약금 · 입금자명이 문자 안 낱말과 같음 · (설정 시) 계좌 끝자리가 문자에 있음
3. 맞는 예약이 1건 → 확정 → 정산 캘린더에 `[감탄예약] 지역 N평 건물 (오전|오후)` 일정 (오전 09시 / 오후 14시, 4시간). 메모에 예약번호·고객·주소·조건·견적·예약금·잔금
4. 같은 이름·같은 금액 예약이 둘이면 판단하지 않고 관리 화면 "확인이 필요한 입금"에 남긴다. 이를 막으려고 신청 때 입금 대기 중인 같은 입금자명이 있으면 숫자를 붙이게 한다(예: 홍길동7)
5. 대기 시간이 지나 들어온 입금(24시간 안): 날짜가 비어 있으면 확정, 그사이 다른 일정이 들어왔으면 `날짜 겹침` → 대표가 연락해 날짜 변경 또는 환불
- 다른 입금(크린토피아 정산 등)은 "짝 없음"으로 기록만 된다
- 같은 문자를 여러 번 보내도 한 번만 처리

## 취소
관리 화면에서 취소하면 캘린더 일정 제목 끝에 `취소확인`이 붙는다(정산 페이지·빈 날짜 계산에서 빠짐). 예약금 환불은 직접 한다.

## 로컬 확인 (배포 없이)
`node tools/dev-server.js` → `http://localhost:8787/reserve/` (고객), `/bookings/#k=` + `k` 40개 (관리), `/__dev` (입금 문자 흉내·초기화). 가짜 저장소·캘린더라 Supabase·구글·Netlify를 쓰지 않는다.

## 배포 전 할 일
1. Supabase에 `supabase/migrations/20261114000000_booking.sql` 적용
2. `/bookings/` 설정에서 단가·예약금 확정, **입금 계좌(은행·번호·예금주) 입력** — 계좌가 없으면 고객은 신청할 수 없다
3. 아이폰 입금 문자 자동화 (위 1번). 문자 형식을 한 번 확인하고 계좌 끝자리를 설정에 넣는다
4. 환경변수는 기존 것 그대로 (`INBOX_TOKEN`, `SUPABASE_*`, `GOOGLE_*`). 서비스 계정은 이미 "일정 변경" 권한

## 대표 확인 필요
- 실제 요금표(평당 요금, 방·화장실·베란다 추가 요금, 지역 출장비, 최소 금액), 예약금, 대기 시간
- `[감탄예약]` 건의 정산 규칙 (지금 정산 페이지는 계산하지 않음 — `handoff.json`은 대표 확인 없이 바꾸지 않는다)
- 예약금 환불 규정 문구, 개인정보 보유 기간(지금 "작업 완료 후 1년")
- 예약 페이지에 넣을 전화번호
