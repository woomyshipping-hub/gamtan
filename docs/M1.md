## 스키마 요약
- `teams`: 1팀(internal, 김한준) / 2팀(external). 팀별 `calendar_id`, 읽기 전용 링크용 `share_token`
- `jobs.status`: `received`(접수) → `confirmed`(확정) → `done`(완료) → `settled`(정산됨). 트리거가 한 칸 이동만 허용(정정용 한 칸 뒤로 허용), 확정부터 팀 배정 필수, 이동마다 `job_status_log` 기록
- `jobs.recv_amount` / `team_amount`: 정산 금액 스냅샷. 계산 규칙은 `handoff.json` 기준 기존 로직 사용
- `day_workers`: 주민번호 전체는 테이블에만, 화면은 `day_workers_masked`(앞 8자리만)
- `ledger_entries`: 수입은 '매출'만, 지출은 인건비·차량·장비·세제·통신비·기타. 일용직 지급은 인건비 + `worker_id`
- RLS: 로그인 사용자 중 `app_owner`에 등록된 이메일만 전체 접근, 익명은 0행. 보안 함수는 API 미노출 `private` 스키마. 팀장님 링크는 서버 함수가 service role로 조회

## 계정 구분
- 개발·관리(Claude, GitHub, Supabase 대시보드, Netlify): 관리 계정 유지
- 운영 시스템 로그인: `app_owner`에 등록된 대표 구글 계정 2개(관리 계정 포함). 둘 다 같은 권한. 이메일 값은 DB에만 두고 저장소에는 적지 않는다
- 구글 로그인용 OAuth 앱이 "테스트" 상태면 대표 로그인 계정을 테스트 사용자로 추가하거나 앱을 게시한다 (email·profile 범위만 써서 구글 심사 불필요)

## 결정 (2026-11-08)
- 캘린더: 지금은 1팀뿐이라 기존 정산 캘린더(`GOOGLE_CALENDAR_ID`)를 그대로 쓴다. `teams.calendar_id`가 비어 있으면 이 캘린더를 쓴다

## 카톡 수신 (`/api/inbox`)
- 요청: `Authorization: Bearer <INBOX_TOKEN>`, 본문 `{"source":"kakao","chat":"채팅방","messages":[{"sender","sent_at","text"}]}` (한 번에 20건까지)
- 같은 메시지를 여러 번 보내도 1건만 저장 (`dedupe_key`). 데스크톱은 겹치게 보내도 된다
- AI 추출이 실패해도 원문은 `state=error`로 남는다
- Netlify 환경변수: `INBOX_TOKEN`(임의 긴 문자열), `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `ANTHROPIC_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`
- 비용: 메시지 20건 1회 처리에 약 1~3원 (Haiku 5.5 입력 $0.10, 출력 $0.50 / 100만 토큰)

## 대표 확인 필요
- 2팀 정산 규칙 (PRD 미결 사항): 정해지기 전까지 2팀은 금액 수동 입력
- 카톡 원문: PC 카카오톡 "김동현 홈클린마스터" 채팅. 이후 상시 켜 둔 데스크톱의 Claude(컴퓨터 사용)가 확인해 `/api/inbox`로 보낸다. 원문은 저장소에 커밋하지 않는다
