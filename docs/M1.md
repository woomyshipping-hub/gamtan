## 스키마 요약
- `teams`: 1팀(internal, 김한준) / 2팀(external). 팀별 `calendar_id`, 읽기 전용 링크용 `share_token`
- `jobs.status`: `received`(접수) → `confirmed`(확정) → `done`(완료) → `settled`(정산됨). 트리거가 한 칸 이동만 허용(정정용 한 칸 뒤로 허용), 확정부터 팀 배정 필수, 이동마다 `job_status_log` 기록
- `jobs.recv_amount` / `team_amount`: 정산 금액 스냅샷. 계산 규칙은 `handoff.json` 기준 기존 로직 사용
- `day_workers`: 주민번호 전체는 테이블에만, 화면은 `day_workers_masked`(앞 8자리만)
- `ledger_entries`: 수입은 '매출'만, 지출은 인건비·차량·장비·세제·통신비·기타. 일용직 지급은 인건비 + `worker_id`
- RLS: 로그인 사용자 중 `app_owner`에 등록된 이메일만 전체 접근, 익명은 0행. 보안 함수는 API 미노출 `private` 스키마. 팀장님 링크는 서버 함수가 service role로 조회

## 카톡 → 캘린더 (`/api/inbox`)
- 요청: `Authorization: Bearer <INBOX_TOKEN>`, 본문 `{"source":"kakao","chat":"채팅방","messages":[{"sender","sent_at","text"}]}` (한 번에 5건까지, 함수 10초 제한). 8초가 지나면 남은 메시지는 `new`로 두고(`deferred`), 1분 이상 지난 `new`는 다음 호출에서 이어서 처리(`resumed`)
- 같은 메시지를 여러 번 보내도 1건만 처리 (`dedupe_key`). 데스크톱은 겹치게 보내도 된다
- 새 일정 (팀장님: 주소·연락처·날짜·시간 형식)
  - 제목 `[자체영업] {지역} {평}평 {건물} ({오전|오후})` — 정산 페이지 제목 규칙 그대로. 평수 없으면 제목에서 빼고 메모에 "평수: 확인 필요"
  - 시간: 메시지의 시작 시각(없으면 오전 09시 / 오후 14시)부터 4시간
  - 메모: 주소, 연락처, 참고, `구분: 자체영업 (홈클린마스터)`, `자동등록: 카톡 …`
  - 같은 날·같은 시간대에 `[자체영업]`/`[홈클린마스터]` 일정이 이미 있으면 만들지 않음 (`duplicate`)
- 추가금 보고 (대표: "오후 추가 7만원있습니다", "오전 추가 없습니다")
  - 보낸 날짜·시간대의 일정 메모 맨 위에 `추가금: 70,000원 (카톡 보고)` (없음은 0원). 기존 `추가금:` 줄은 교체
  - 시간대 일정이 1건이 아니면 건드리지 않고 `unmatched`
- 처리 결과는 `inbox_messages.state`: created / duplicate / extra_applied / unmatched / ignored / error (원문은 항상 남음)
- 필요 권한: 서비스 계정이 정산 캘린더를 **"일정 변경"** 권한으로 공유받아야 한다 (지금은 "보기")
- Netlify 환경변수: `INBOX_TOKEN`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`(새 비밀 키 `sb_secret_…` 또는 예전 service_role 키), `ANTHROPIC_API_KEY`, 기존 `GOOGLE_SERVICE_ACCOUNT_JSON`·`GOOGLE_CALENDAR_ID`. `TELEGRAM_*`는 쓰지 않음
- 운영 측정(2026-11-08): 일정 등록+추가금 2건 9.4초 → 개선 전. AI만 1건 2.4~2.7초, 재전송(중복) 0.8초
- 비용: 메시지 5건 1회 처리에 약 1원 (Haiku 5.5 입력 $0.10, 출력 $0.50 / 100만 토큰)

## 장부 (`/ledger/`, `/api/ledger`)
- 열기: `https://gamtan-kr.netlify.app/ledger/#k=<키>`. 처음 열면 키를 그 브라우저에 저장하고 주소창에서는 지운다
- 키: `access_keys(name='ledger')`에 sha256만 저장. 바꾸려면 새 키의 sha256으로 행을 바꾼다 (이전 주소는 바로 막힘)
- 금액 입력: `35만`, `3.5만`, `35만5천`, `82,000` 모두 인식
- 분류: 수입 = 매출 / 지출 = 인건비·차량·장비·세제·통신비·기타. 일용직 지급은 인건비 + 일용직 선택
- 주민번호: `day_workers.rrn`에만 저장, 화면·API는 `day_workers_masked`(앞 8자리)만
